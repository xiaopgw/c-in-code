Git作用
Git简介
Git诞生史
集中式VS分布式
集中式
典型代表：SVN
特点：所有的版本库都存在中央服务器，本地备份动作必须依赖中央服务器，如果一旦服务器挂掉，或者网络状况不好，没法提交版本。
分布式
典型代表：Git
特点：每一台客户端都有完整的版本备份，所有的版本提交不需要依赖中央服务器，只有多人协作时候，需要用服务器交换一下版本库。

常用托管平台
[Github]

开源项目的聚集地，世界最大的代码托管平台。很多著名的项目都在Github开源，比如Linux源码、Qt源码等。缺点：国内经常无法访问，速度比较慢。

[Gitlab]

Gitlab支持公有仓库和免费的私有仓库，体验和Github类似，常用作搭建的企业内网代码托管平台。公有仓库国内经常无法访问，速度比较慢。

[码云]

国内代码托管的老大，一个账号最多可以创建1000个项目，不分公有和私有。速度非常快，体验较好。会同步国外知名的开源项目，下载速度快。搜Gitee 极速下载，里边搜Linux kernel就可以看到Linux内核的源码。

项目忽略文件
有些时候，你必须把某些文件放到Git工作目录中，但又不能提交它们，比如保存了数据库密码的配置文件啦，等等，每次git status都会显示Untracked files ...，有强迫症的童鞋心里肯定不爽。
解决方案
.gitignore 是 Git 版本控制系统中一个非常重要的配置文件，用于指定哪些文件或目录应该被 Git 忽略，即不被纳入版本控制。以下是一份详细的介绍：
● 避免将临时文件、日志、编译产物等无关文件提交到仓库。
● 防止敏感信息（如密码、密钥、配置文件）意外上传。
● 减少仓库体积，提高协作效率。
注意：这个忽略文件一定要在项目之初创建好，并放到工程目录中

如果已经提交了，再增加到忽略文件是不生效的，此时需要通过特定选项来删除。
● 选择删除并添加到忽略列表

● 只忽略一个文件还是忽略所有的同类型文件自己来决定。

● 完成后需要再提交推送一次，后续的提交就不会再显示忽略掉的文件了。
