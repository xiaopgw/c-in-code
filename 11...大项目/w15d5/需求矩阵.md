# 智能家居中控大屏（LVGL）详细设计

> 归属：大项目 / 设备端 - STM32U5 中控面板
> 关联：本文件上方"需求矩阵"中的"应用层 / 网关层 / 设备端"

## 0. 项目定位

用 STM32U5 的 2.8 寸触摸屏作为全屋中控面板，通过 WiFi 接入 MQTT 网络，实时显示并控制挂在网络中的各类设备；配套 Linux 网关（Modbus + MQTT + sqlite3 + WebServer）与网页端。

核心看点：一块能实时联动的嵌入式触摸屏（非静态界面），以及"屏 -> 云端 -> 设备"的完整闭环。

## 1. 目标与范围

### MVP（1.5 周内必须闭环）
- U575：LVGL 界面运行，触摸可操作，能实时显示数据
- 三块板接入同一 MQTT 网络，设备状态双向实时更新
- Linux 网关：MQTT 汇聚 + sqlite3 存储
- Web 端可看状态、可控制

### 加分项（有余力再做，按优先级）
- 屏上历史曲线页（lv_chart）
- Web 端 ECharts 趋势图
- ESP32-S3 离线语音命令词
- QT 客户端
- 深色科技风主题与动画

## 2. 硬件与角色分配

| 板子 | 角色 | 承担 | 接口 |
|------|------|------|------|
| STM32U575 | 中控大屏（主角） | LVGL 界面、触摸交互、数据展示与控制 | 屏 SPI(ILI9341)，触摸 I2C(FT6336G)，联网 板载 ESP-12F(AT) |
| ESP32-S3 | 无线节点（可选语音） | 自带 WiFi 直连 broker，上报环境数据，命令词识别 | WiFi、麦克风 |
| STM32F103 | 执行节点（工业范） | 继电器/灯/风扇控制，Modbus RTU 从机 | UART -> RS485/USB 转串口 |
| Linux 主机 | 网关 | broker、Modbus 主站、sqlite3、WebServer | 网口/USB |

## 4. U575 中控端软件架构（FreeRTOS）

| 优先级 | 任务 | 职责 | 同步机制 |
|--------|------|------|---------|
| 高 | Task_Comm | 串口收发包 + cJSON 解析 | Queue -> 其它任务 |
| 中 | Task_Gui | lv_timer_handler() 10ms | Mutex(lvgl 锁) |
| 中 | Task_Touch | 读 FT6336G，喂 LVGL 输入 | - |
| 低 | Task_Sensor | 本地采集（板载加速度等） | Queue |
| 低 | Task_Actuator | 本地 GPIO（LED/蜂鸣器） | - |

关键原则（务必遵守）：

1. LVGL 不是线程安全的：只有 Task_Gui 能调用 lv_*，其它任务通过队列投递数据或加互斥锁。
2. LVGL 移植三件套：lv_port_disp（flush_cb 用 SPI+DMA 刷屏）、lv_port_indev（读触摸坐标）、lv_tick_inc（接 FreeRTOS 滴答或定时器）。
3. 刷屏用 DMA：一帧 320x240x2=150KB，必须 DMA + 局部刷新，否则撕裂/卡顿。
4. 数据流：Task_Comm 收 JSON -> 入队 -> Task_Gui 出队 -> 更新 label/chart。

U575 联网方案（二选一）：

| 方案 | 做法 | 优点 | 风险 |
|------|------|------|------|
| A 稳妥（推荐） | U575 <-> UART(JSON) <-> ESP32-S3，由 ESP32-S3 跑成熟 MQTT 库连 broker | 不用裸机写 MQTT | 多一层协议 |
| B 进阶 | U575 用板载 ESP-12F（AT+TCP），自己实现 MQTT 最小报文集 | 技术含量高、板载即用 | 报文拼装易错，约 250 行 |

建议：主线走 A，把 B 作为进阶彩蛋。

## 5. 界面设计（320x240）

5 个页面，建议卡片式 + 深色科技风：

```
[1] 主页/仪表盘   温度/湿度卡片 + 设备状态卡片 + 底部导航
[2] 设备控制页    灯(开关) / 风扇(滑块) / 蜂鸣器(开关)
[3] 历史曲线页    lv_chart 曲线
[4] 设置页        WiFi / 时间 / 主题
[5] 语音/弹窗     提示与报警
```

控件：lv_obj 卡片 + lv_label 数值 + lv_switch/lv_slider 控制 + lv_chart 曲线；状态用颜色区分（开=绿，关=灰，报警=红）；触摸事件用 lv_obj_add_event_cb。

## 6. 通信协议（Day0 冻结）

### 6.1 MQTT 主题

```
home/up/{devid}      设备 -> 云端（数据上报）
home/down/{devid}    云端 -> 设备（控制命令）
home/panel/state     中控面板自身状态
```

### 6.2 JSON 格式

上报：

```json
{ "dev": "u575-panel", "ts": 1757548800, "t": 26.5, "h": 60, "light": 320, "led": 1, "fan": 0 }
```

控制：

```json
{ "dev": "f103-01", "cmd": "led", "val": 1 }
```

### 6.3 数据点字典

| ID | 含义 | 单位 | 类型 |
|----|------|------|------|
| t | 温度 | 摄氏度 | float |
| h | 湿度 | % | int |
| light | 光照 | lux | int |
| led | 灯 | 0/1 | int |
| fan | 风扇 | 0-100 | int |
| buzzer | 蜂鸣器 | 0/1 | int |

## 10. 风险与降级预案

| 风险 | 概率 | 降级方案 |
|------|------|---------|
| ILI9341 驱动不通 | 中 | 降低 SPI 速率 / 软件 SPI / 用课程现成驱动 |
| 触摸 FT6336G 不通 | 中 | 降级为五向按键操作 |
| LVGL 移植卡住 | 中 | 用官方 lv_port 模板 |
| U575 WiFi/MQTT 不通 | 中 | 走方案 A 由 ESP32-S3 代传；再不行串口直连 PC 代理 |
| Modbus 时序问题 | 中 | 先用私有串口协议跑通，再包装成 Modbus |
| 时间不够 | 高 | 按序砍：QT -> 历史曲线 -> 语音 -> 美化 |
| 内存爆 | 低 | 缓冲区调小、减少控件、关动画 |

判断标准：模块到 Day5 未通且无退路 -> 立刻降级。
