## 一、IP 地址基本概念

● IP 地址是 Internet 中主机的标识（电脑本身还自带一个物理标识 MAC 地址，两者需要区分）
● Internet 中的主机要与别的机器通信，必须具有一个 IP 地址
● IP 地址为 32 位（IPv4）或者 128 位（IPv6）
● 每个数据包都必须携带目的 IP 地址和源 IP 地址，路由器依靠此信息为数据包选择路由
● 表示形式：常用点分十进制形式，如 202.38.64.10，最后都会转换为一个 32 位的无符号整数
● 地址构成：
  - 二级划分 = 网络号 + 主机号
  - 三级划分 = 网络号 + 子网号 + 主机号
  - 网络号：表示是否在同一个网段
  - 主机号：同一个网段内主机 ID，并且只能有一个

两个主机能不能直接通信，先看"网络号"是否相同：网络号相同属于同一网段（可经交换机二层转发），网络号不同必须经过路由器（网关）转发。

## 二、IP 地址的分类（A ~ E 类）

按第一个字节的高位区分：

| 类别 | 首字节高位 | 地址范围 | 默认子网掩码 | 用途 |
|------|-----------|----------|--------------|------|
| A 类 | 0 | 0.0.0.0 ~ 127.255.255.255 | 255.0.0.0 | 大型网络 |
| B 类 | 10 | 128.0.0.0 ~ 191.255.255.255 | 255.255.0.0 | 中型网络 |
| C 类 | 110 | 192.0.0.0 ~ 223.255.255.255 | 255.255.255.0 | 小型网络/局域网 |
| D 类 | 1110 | 224.0.0.0 ~ 239.255.255.255 | 无 | 组播（多播）地址 |
| E 类 | 1111 | 240.0.0.0 ~ 255.255.255.255 | 无 | 保留（科研/实验） |

■ 注意：笔记原文写的是"C：192.0.0.0 ~ 233.255.255.255""E：240.0.0.0 ~ 247.255.255.255"，其中 233 与 247 属于笔误，按标准应为 223 与 255。

各类地址可容纳的主机数（去掉网络地址和广播地址，再减 2）：

| 类别 | 主机号位数 | 主机数 |
|------|-----------|--------|
| A 类 | 24 | 2^24 - 2 = 16777214 |
| B 类 | 16 | 2^16 - 2 = 65534 |
| C 类 | 8 | 2^8 - 2 = 254 |

> 练习（笔记原题）：C 类地址，同一网段最多可以连接多少个主机？
> 答案：256 - 2 = 254（首地址是网络地址，末地址是广播地址，都不能分配给主机）

<< 拓展（课程外补充） >> 私有 IP 地址（不能在公网路由，常用于局域网）：
10.0.0.0 ~ 10.255.255.255（10.0.0.0/8）、172.16.0.0 ~ 172.31.255.255（172.16.0.0/12）、192.168.0.0 ~ 192.168.255.255（192.168.0.0/16）。笔记中出现的 192.168.50.x、192.168.1.x、172.25.227.x 都属于这一类。

## 三、特殊 IP 地址（不能分配给主机使用）

1. 网络地址：用于标识网络的起始地址 = 有效网络号 + 全是 0 的主机号

```
192.168.50.10  ---->  192.168.50.0
128.3.10.7     ---->  128.3.0.0
20.2.3.5       ---->  20.0.0.0
```

2. 广播地址：用于给局域网内所有主机发送数据 = 有效网络号 + 全是 1 的主机号

```
以 192.168.1.0（掩码 255.255.255.0）网段为例：
最大的主机地址 192.168.1.255 就是该网段的广播地址，发到该地址的数据包被该网段所有主机接收
```

3. 0.0.0.0 / INADDR_ANY（服务器专用）

● 0.0.0.0 指的是监听本机上所有的 IPv4 地址
● 接收来自任意源 IP 地址的数据包，常用于服务器程序监听所有网络接口的连接请求
● 代码里两种等价写法：`addr.sin_addr.s_addr = INADDR_ANY;` 或 `htonl(INADDR_ANY)`

4. 127.0.0.1：回环地址 / 本机地址

● 一般用来测试使用，所有发往该类地址的数据包都应该被 loop back（原样送回）
● 当在计算机上访问 127.0.0.1 时，实际上是在与自己进行网络通信
● 整个 127.0.0.0/8 网段都属于回环地址（127.0.0.1 ~ 127.255.255.254 均可作为回环）

5. 255.255.255.255：本地网络广播（受限广播），只在本网段内广播，路由器不转发

6. 组播（多播）地址：D 类 IP

● 不分网络地址和主机地址，第 1 字节的前 4 位固定为 1110，即 D 类 IP
● 范围：224.0.0.1 ~ 239.255.255.255
● 224.0.0.0 ~ 224.0.0.255 为预留的组播地址（永久组地址），其中 224.0.0.0 保留不做分配，其它地址供路由协议使用
● 224.0.1.0 ~ 224.0.1.255 是公用组播地址，可以用于 Internet
● 224.0.2.0 ~ 238.255.255.255 为用户可用的组播地址（临时组地址），全网范围内有效
● 239.0.0.0 ~ 239.255.255.255 为本地管理组播地址，仅在特定的本地范围内有效

三种发送方式对比：

| 方式 | 接收方 | 说明 |
|------|--------|------|
| 单播 | 一个接收方 | 普通的数据包发送方式 |
| 广播 | 局域网内所有主机 | 只有用户数据报（UDP）套接字才能广播，一般设计成局域网搜索协议；过多广播会造成广播风暴、占用带宽 |
| 组播 | 加入多播组的主机 | 一个人发送，加入多播组的人接收；既能发给多个主机，又避免广播那样带来过多负载 |

（组播/广播属于 IP 地址分类的直接应用，细节见 `w7d5/UDP服务器.md` 第 3、4 节）

## 四、子网掩码

作用：将 IP 地址划分成网络地址和主机地址

特点：
1) 子网掩码长度和 IP 地址长度完全一样，由 32 bit 二进制数组成
2) 网络号全为 1，主机号全为 0
3) 各类地址的默认子网掩码：

```
A 类：255.0.0.0
B 类：255.255.0.0
C 类：255.255.255.0
```

4) 掩码必须由连续的 1 加连续的 0 组成，常见掩码与位数对应：

| 掩码 | 前缀 | 可用主机数 |
|------|------|-----------|
| 255.255.255.0 | /24 | 254 |
| 255.255.255.128 | /25 | 126 |
| 255.255.255.192 | /26 | 62 |
| 255.255.255.224 | /27 | 30 |
| 255.255.255.240 | /28 | 14 |

三个关键计算：

```
网络地址 = IP 地址  &  子网掩码        （按位与）
广播地址 = 网络地址 | (~子网掩码)      （主机位全置 1）
可用主机范围 = 网络地址 + 1  ~  广播地址 - 1
主机数 = 2^主机位数 - 2
```

> 练习（笔记原题）：子网掩码 255.255.255.0，该网段可以容纳多少台主机？
> 答案：254

## 五、三级划分（子网划分）

二级地址 = 网络号 + 主机号
三级划分 = 网络号 + 子网号 + 主机号

思路：从"主机号"里借出若干位当"子网号"，借 n 位就能划分出 2^n 个子网。

步骤：
1. 由需要的子网个数确定要借的位数 n（2^n ≥ 子网数）
2. 写出新的子网掩码（网络位 + 子网位全 1，剩余主机位全 0）
3. 按子网号依次枚举，写出每个子网的网络地址、可用地址范围、广播地址
4. 校验每个子网的可用主机数是否满足需求（2^主机位 - 2 ≥ 每子网主机数）

> 练习（笔记原题）：
> 某公司有四个部门：行政、研发1、研发2、营销，每个部门各 40 台计算机接入公司局域网交换机，如果要在 192.168.1.0 网段为每个部门划分子网，子网掩码应该怎么设置，每个子网的地址范围分别是什么？（4 个部门之间不能通信）
>
> 解答：
> 划分 4 个子网 ---> 分 2 位子网 ---> 子网掩码：255.255.255.192（/26）
> 每个子网可用主机数 = 2^6 - 2 = 62 ≥ 40，满足要求
> 按照子网号，进一步写出每一个子网的 IP 地址范围：
>
> ```
> 00    192.168.1.1    ~  192.168.1.62    （广播 192.168.1.63）
> 01    192.168.1.65   ~  192.168.1.126   （广播 192.168.1.127）
> 10    192.168.1.129  ~  192.168.1.190   （广播 192.168.1.191）
> 11    192.168.1.193  ~  192.168.1.254   （广播 192.168.1.255）
> ```

子网划分带来的实际结果：不同子网之间不能直接通信（网络号不同），必须经过路由器/三层交换或者网关才能互通；只有同一子网内的主机才能直接通信。

## 六、字节序与 IP 地址的存储/转换

### 6.1 字节序

1. 字节序是指不同类型的 CPU 主机，内存存储"多字节整数"序列的方式
2. 浮点类型、字符类型、字符串没有字节序
3. 小端序（little-endian）：低序字节存储在低地址（主机字节序，x86 就是小端）
4. 大端序（big-endian）：高序字节存储在低地址（网络字节序）

结论：IP 地址和端口号放进结构体之前，必须由主机字节序转换成网络字节序，否则对端解析出来是错的。

### 6.2 主机字节序 <-> 网络字节序

```c
/* 主机字节序 -> 网络字节序 */
u_long  htonl(u_long hostlong);   // 用于 32 位：IP 地址
u_short htons(u_short hostshort); // 用于 16 位：端口号（重点掌握）

/* 网络字节序 -> 主机字节序 */
u_long  ntohl(u_long netlong);    // 用于 32 位：IP 地址
u_short ntohs(u_short netshort);  // 用于 16 位：端口号
```

记忆：h = host 主机，n = net 网络，s = short（2 字节），l = long（4 字节）。
写进结构体用 h 打头的（htonl/htons），从结构体里读出来打印用 n 打头的（ntohl/ntohs）。

### 6.3 IP 地址转换函数

`man inet_addr` 查看手册：

```c
typedef uint32_t in_addr_t;

struct in_addr
{
    in_addr_t s_addr;
};

in_addr_t inet_addr(const char *ip);      // 从人看的点分十进制 -> 机器使用的 32 位无符号整数
char     *inet_ntoa(struct in_addr in);   // 从机器使用的整数 -> 人看的点分十进制
```

要点：

● `inet_addr` 返回的就是**网络字节序**的整数，所以可以直接赋给 `sin_addr.s_addr`，不需要再 htonl
● `inet_ntoa` 的参数是结构体（不是指针），一般配合 `addr.sin_addr` 使用，返回字符串指针
● `inet_addr` 是 IPv4 专用；IPv6 或新接口用 `inet_pton` / `inet_ntop`
● `INADDR_ANY` 表示 0.0.0.0（本机所有网卡），可以直接赋给 s_addr，也可以写成 `htonl(INADDR_ANY)`

## 七、IP 在网络编程中的结构体表示

### 7.1 通用结构体 sockaddr

```c
struct sockaddr {
    sa_family_t sa_family;
    char        sa_data[14];
};
```

bind()、connect()、accept()、recvfrom()、sendto() 这几个函数的地址参数用的都是"通用结构体"，实际填充时必须根据通信方式（socket 第一个参数）填对应的专用结构体，最后强制转换为 `(struct sockaddr *)`。

### 7.2 IPv4 专用结构体 sockaddr_in

```c
struct sockaddr_in
{
    sa_family_t    sin_family; /* 地址族: AF_INET */
    u_int16_t      sin_port;   /* 按网络字节次序的端口 */
    struct in_addr sin_addr;   /* internet 地址 */
};

/* Internet 地址 */
struct in_addr
{
    u_int32_t s_addr; /* 按网络字节次序的地址 */
};
```

三个成员的填法：

| 成员 | 填什么 | 是否需要字节序转换 |
|------|--------|-------------------|
| sin_family | AF_INET（IPv4）/ AF_INET6（IPv6）/ AF_UNIX、AF_LOCAL（本地） | 否 |
| sin_port | 端口号 | 是，用 htons() |
| sin_addr.s_addr | 服务器 IP / 客户端 IP / INADDR_ANY | inet_addr() 已转换；INADDR_ANY 可不转换 |

### 7.3 与 IP 同层的概念：端口号（关联知识点）

● 为了区分一台主机接收到的数据包应该转交给哪个进程来处理，使用端口号来区分
● TCP 端口号与 UDP 端口号独立
● 端口号一般由 IANA（Internet Assigned Numbers Authority）管理
● 端口用两个字节表示（2 byte，范围 0 ~ 65535）

```
众所周知端口：1~1023（1~255 之间为众所周知端口，256~1023 端口通常由 UNIX 系统占用）
已登记端口：1024~49151（选 1000 以上、10000 以下，如 8888、8000、9999）
动态或私有端口：49152~65535
```

常用端口：80（HTTP）、502（Modbus TCP）、8080（HTTP 备用，笔记中的 WebServer 用的就是它）、520（wireshark 过滤示例中用到的端口）。

IP + 端口才能唯一确定"哪台机器的哪个进程"：IP 定位到主机，端口定位到进程（端到端）。

## 八、代码中的 IP 典型写法

### 8.1 服务器：监听本机所有 IP

```c
struct sockaddr_in addr, addrci;
int len = sizeof(addrci);

addr.sin_family      = AF_INET;         // 地址族
addr.sin_port        = htons(25565);    // 端口号（网络字节序）
addr.sin_addr.s_addr = INADDR_ANY;      // 本机所有 IPv4 地址（等价 0.0.0.0）

bind(sockfd, (struct sockaddr *)&addr, sizeof(addr));

/* accept 之后打印客户端 IP 和端口（来电显示功能） */
accept(sockfd, (struct sockaddr *)&addrci, &len);
printf("IP为: %s %d的客户端已连接\n", inet_ntoa(addrci.sin_addr), ntohs(addrci.sin_port));
```

另一处写法（WebServer/thttpd）：

```c
local.sin_family      = AF_INET;
local.sin_port        = htons(_port);
local.sin_addr.s_addr = INADDR_ANY;
```

### 8.2 客户端：指定要连接的服务器的 IP

```c
struct sockaddr_in addr;
addr.sin_family      = AF_INET;
addr.sin_port        = htons(25565);
addr.sin_addr.s_addr = inet_addr("192.168.50.141");  // 字符串 -> 32 位网络字节序整数

connect(sockfd, (struct sockaddr *)&addr, sizeof(addr));
```

### 8.3 IP 字符串与整数互转的验证

```c
struct in_addr in;
in.s_addr = inet_addr("185.199.110.153");  // 字符串 -> 32 位无符号整数
char *arr = inet_ntoa(in);                 // 整数 -> 字符串
printf("IP为: %s\n", arr);
```

### 8.4 UDP 广播：目的 IP 填广播地址 + 开启广播属性

```c
struct sockaddr_in saddr;
saddr.sin_family      = AF_INET;
saddr.sin_port        = htons(8080);
saddr.sin_addr.s_addr = inet_addr("192.168.50.255"); // 该网段的广播地址

int opt = 1;
setsockopt(sockfd, SOL_SOCKET, SO_BROADCAST, &opt, sizeof(opt)); // 允许发送广播数据
sendto(sockfd, buf, sizeof(buf), 0, (struct sockaddr *)&saddr, len);
```

### 8.5 Modbus TCP 客户端的 IP 与端口

```c
struct sockaddr_in addr;
addr.sin_family      = AF_INET;
addr.sin_port        = htons(502);                    // Modbus TCP 默认端口
addr.sin_addr.s_addr = inet_addr("192.168.50.65");    // 从机（PLC）IP
connect(sockfd, (struct sockaddr *)&addr, sizeof(addr));
```

## 九、IP 相关命令与调试

### 9.1 ping

作用：
● 用来检测网络的连通情况
● 根据域名得到服务器 IP
● 根据 ping 返回的 TTL 值来判断数据包经过路由器的数量

原理：ping 使用的是 **ICMP** 协议，属于网络层（"网络控制管理协议"）。

### 9.2 netstat（测试网络状态）

```
netstat -a    // 查看所有网络连接状态
netstat -at   // 查看 TCP 所有网络状态
netstat -au   // 查看 UDP 所有网络状态
```

### 9.3 wireshark 过滤 IP

```
过滤端口：tcp.port == 520
过滤 IP：  ip.addr == 192.168.0.105   （写自己的 IP 地址）
多个条件同时过滤时用 && 连接
```

wireshark 抓包时先选网卡：有线选本地连接/以太网，无线选 WLAN，本机内部通信选 NPCAP Loopback adapter（Adapter for loopback traffic capture）。

### 9.4 IP 与协议栈的关系（抓包分析用）

● 网络层（IP 层）：负责主机到主机的寻址与路由，IP 头里有源 IP 和目的 IP
● 网络层最大数据帧长度 1500 字节；链路层最大数据长度 1518 字节（1500 + 14 + CRC）
● 发送时，IP 层协议栈程序检测到发送数据和包头总长度超过 1500 字节时，会自动分包处理；接收端在 IP 层重组后再继续往上传递
● 相关协议：ARP（IP -> MAC）、RARP（MAC -> IP）、IP（IPv4/IPv6 网间互连协议）、ICMP（ping 使用）、IGMP（广播和组播使用）

### 9.5 查看/配置本机 IP 的常见命令（拓展补充）

```
ip addr            // 查看本机所有网卡的 IP（推荐）
ifconfig           // 老命令，查看/配置网卡 IP
ip route           // 查看路由表，确认默认网关
```

## 十、易错点与面试问答

1. IP 地址和 MAC 地址的区别？
   IP 地址是逻辑地址（32 位 IPv4 / 128 位 IPv6，可变、用于跨网段寻址），MAC 地址是物理地址（网卡出厂固化，用于同一链路内的寻址）；跨网段通信时目的 IP 不变，但目的 MAC 会逐跳改变（由 ARP 解析）。

2. 为什么每个网段可用主机数要减 2？
   网络号 + 主机号全 0 是网络地址，主机号全 1 是广播地址，两者都不能分配给主机。

3. inet_addr 之后还要不要 htonl？
   不要。inet_addr 返回的已经是网络字节序，再 htonl 反而会错。反过来，把 32 位主机字节序整数（如自定义常量）赋给 s_addr 时才需要 htonl。

4. 打印客户端端口为什么用 ntohs 而不是 htons？
   accept/recvfrom 拿到的结构体里已经是网络字节序，要给"人"看（打印到终端）必须用 ntohs 转回主机字节序；htons 是"主机 -> 网络"，方向反了。
   实例：`w7d4/sever.c` 第 52 行原来写成 `htons(addrci.sin_port)`，已修正为 `ntohs(addrci.sin_port)`；`w7d6`、`w7d7`、`w8d2`、`w8d1` 下的 sever.c 原本就是 `ntohs`，写法正确。

5. INADDR_ANY / 0.0.0.0 和 127.0.0.1 有什么区别？
   0.0.0.0 用在服务器 bind 阶段，表示监听本机所有网卡（所有 IPv4 地址），客户端可以拿任意一个本机 IP 连上；127.0.0.1 是回环地址，只能自己访问自己，通常用于本机测试。

6. 广播和组播的区别？
   广播发给本网段所有主机（地址为主机位全 1，如 192.168.1.255；或受限广播 255.255.255.255），会造成额外开销甚至广播风暴；组播只发给加入多播组的主机（D 类地址 224.0.0.1~239.255.255.255），既省带宽又能一对多。

7. 同一网段怎么判断？
   IP 与子网掩码按位与得到网络地址，网络地址相同即同一网段。

8. TCP/IP 模型中 IP 在哪一层？
   在网络层（Internet Layer），负责"通过 IP 寻址机器"，提供设备到设备的传输；上层传输层再通过端口号找到具体进程。

## 十一、网络模型

> 内容来源：`w7d4/cocket网络编程.md` 第 3 节（网络的体系结构 / OSI 模型 / TCP/IP 模型 / 常见网络协议）、`w8d1/select并发服务器.md` 第 2 节（数据封装与传递 / 以太网帧格式 / wireshark 与 OSI 七层对应）、`0...华清知识库` 中 TCP/IP 模型与 OSI 模型的问答。

### 11.1 为什么分层：网络的体系结构

● 网络采用分而治之的方法设计，将网络的功能划分为不同的模块，以分层的形式有机组合在一起
● 每层实现不同的功能，其内部实现方法对外部其他层次来说是透明的；`每层向上层提供服务，同时使用下层提供的服务`
● `网络体系结构即指网络的层次结构和每层所使用协议的集合`
● 两类非常重要的体系结构：OSI 与 `TCP/IP`；其中 OSI 是最理想的模型，TCP/IP 是实际落地使用的模型

### 11.2 OSI 七层模型（自上而下）

| 层次 | 作用（笔记要点） |
|------|------------------|
| 应用层 | 指定特定应用的协议：文件传输、文件管理、电子邮件等 |
| 表示层 | 确保一个系统应用层发送的消息可以被另一个系统的应用层读取；编码转换、数据解析、数据加密解密 |
| 会话层 | 通信管理，负责建立或者断开通信连接 |
| 传输层 | 端口号；数据传输到具体哪个进程程序处理（端到端） |
| 网络层 | 路由器中是有算法的，IP；主机到主机、路由的转发 |
| 链路层 | 格式变为帧（把数据分成包，一帧一帧的数据进行发送） |
| 物理层 | 传输的是 bit 流（0 与 1 一样的数据）、物理信号，没有格式 |

记忆顺序（自下而上）：物理层 -> 链路层 -> 网络层 -> 传输层 -> 会话层 -> 表示层 -> 应用层。

### 11.3 TCP/IP 四层模型（自下而上）

● 网络接口和物理层：屏蔽硬件差异（驱动），向上层提供统一的操作接口
● 网络层：提供端对端的传输，可以理解为通过 IP 寻址机器
● 传输层：决定数据交给机器的哪个任务（进程）去处理，通过端口寻址
● 应用层：应用协议和应用程序的集合

■ 注意（易错）：笔记原文说网络层"提供端对端的传输"，严格讲网络层是**主机到主机**，**端到端（进程到进程）是传输层**的职责。答题时按"网络层主机到主机（IP 寻址）、传输层端到端（靠端口）"来说更稳。

### 11.4 OSI 与 TCP/IP 对照

| OSI 七层 | TCP/IP 四层 |
|----------|-------------|
| 应用层 / 表示层 / 会话层 | 应用层 |
| 传输层 | 传输层 |
| 网络层 | 网络层 |
| 数据链路层 / 物理层 | 网络接口和物理层 |

### 11.5 常见网络协议（按层归类，笔记原文）

```
网络接口和物理层:
    PPP:拨号协议(老式电话线上网方式)
    ARP:地址解析协议 IP-->MAC
    RARP:反向地址转换协议 MAC-->IP
网络层:
    IP(IPV4/IPV6):网间互连的协议
    ICMP:网络控制管理协议，ping 命令使用
    IGMP:网络分组管理协议，广播和组播使用
传输层:
    TCP:传输控制协议
    UDP:用户数据报协议
应用层:
    SSH:加密协议
    telnet:远程登录协议
    FTP:文件传输协议(TCP)
    TFTP:简单文件传输协议（UDP）
    HTTP:超文本传输协议（明文发送）HTTPS 加密传输
    DNS:域名解析协议
    SMTP/POP3:邮件传输协议
```

### 11.6 数据的封装、传递与解封装

● 发送方自上而下逐层加头：应用数据 -> 传输层加 TCP/UDP 头（含端口）-> 网络层加 IP 头（含源 IP 和目的 IP）-> 链路层加帧头帧尾 -> 物理层变成 bit 流发出
● 每层只处理自己的头部，向上层提供服务，同时使用下层提供的服务（分层的好处：改一层不影响其它层）
● 网络层最大数据帧长度 1500 字节；链路层最大数据长度 1518 字节（1500 + 14 帧头 + CRC）
● 发送时，IP 层协议栈程序检测到"发送数据 + 包头"总长度超过 1500 字节时，会进行自动分包处理；接收端在 IP 层完成包重组，然后才继续往上传递
● 抓包时 wireshark 的帧列表与 OSI 七层模型逐层对应，可以展开看每一层的头部
● TCP 的三次握手、四次挥手属于传输层的行为，抓包里表现为 SYN / ACK / FIN 报文（详见 `w8d1/select并发服务器.md`）

### 11.7 面试问答

1. TCP/IP 网络模型分为几层？每层什么作用？都有哪些协议？
   四层：应用层（应用协议和应用程序的集合，HTTP/FTP/SMTP/DNS/Telnet/SSH/SNMP）、传输层（端到端，通过端口寻址，TCP/UDP）、网络层（通过 IP 寻址机器，IP/ICMP/IGMP）、网络接口和物理层（屏蔽硬件差异，Ethernet/PPP/ARP/RARP）。

2. OSI 模型分几层？
   七层：物理层、数据链路层、网络层、传输层、会话层、表示层、应用层（各层职责见 11.2）。

3. OSI 和 TCP/IP 是什么关系？
   OSI 是最理想的模型，层次划分更细、更清晰，作为理论参考；TCP/IP 是实际使用的体系结构，把 OSI 的上三层合并成应用层、下两层合并成网络接口和物理层，共四层。<< 拓展 >>

4. 为什么要分层？
   分而治之，每层功能独立、内部实现对其他层透明；每层向上层提供服务并使用下层提供的服务，某一层的实现变化不影响其它层。

5. IP 协议、端口号、MAC 地址分别在模型的哪一层？
   IP 在网络层（提供主机到主机的寻址和路由），端口号在传输层（找到具体进程），MAC 地址在链路层的帧头里用于同一链路内的寻址。<< 拓展 >>
